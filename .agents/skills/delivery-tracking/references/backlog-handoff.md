# Backlog Handoff


1. Read clarified scope, traceability, WBS, estimates, risks and reviewed assessment.
2. Write backlog-handoff.md with target platform, Epic/Feature/Story/Task mapping as appropriate, stable local IDs,
   AC, dependencies, proposed owner, effort range, evidence and readiness blockers.
3. Mark tracker IDs unknown until a read-only lookup supplies them. Separate proposed resource assignment
   from assignment actually recorded in a tracker.
4. Provide idempotency/import mapping and a checklist for the authorized executor; do not create issues,
   send messages, change sprints or assign people through external tools from this skill.
5. Keep development implementation plans separate from resource-constrained project schedules.
6. If the user explicitly requests tracker mutation, route to the relevant connected capability with verified
   recipients/project and exact reviewable payload. This repository ships no ADO/Jira/GitHub connector.
