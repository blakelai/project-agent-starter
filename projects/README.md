# Baselines and execution

After explicit project-owner acceptance, create `<project-id>/baseline/<version>/` with exact copies of
requirements, WBS, estimates, evidence, decisions, risks, calendar/capacity and schedule outputs. Record
approval evidence, source revisions and SHA-256 manifest. Baselines are immutable; changes supersede them.

The starter has no accepted real baseline and makes no delivery commitment. Execution progress belongs in
requirement progress.yaml and reviewed status reports. V1 scheduler is full-WBS planning only.
